# Трансляція з камери на сайт

## Як це влаштовано

```
камера на полі -> реєстратор -> (інтернет) -> сервер -> YouTube -> плеєр на сайті
```

Маленький сервер в інтернеті цілодобово забирає відео з реєстратора й передає
його в YouTube. Сайт показує звичайний плеєр YouTube.

Чому через YouTube: глядачі вантажать відео з YouTube, а не з камери. Скільки б
їх не було — хоч сто на матчі — інтернет стадіону віддає рівно один потік,
а сервер лишається маленьким і дешевим. Якщо роздавати відео самотужки, кожен
глядач з'їдав би ще півтора мегабіта вихідного каналу стадіону.

Затримка — 15–30 секунд. Для перегляду гри це не заважає.

## Що знадобиться

- **Сервер** — найдешевший VPS, 1 ядро і 1 ГБ пам'яті (Hetzner CX22 ≈ 4 €/міс,
  є й українські хостери). Ubuntu 24.04.
- **Канал YouTube** у замовника. Трансляції вмикаються не одразу: після
  підтвердження номера телефона YouTube відкриває їх **через 24 години**.
- **Доступ до роутера стадіону**, щоб пропустити до реєстратора один порт.

## Крок 1. Користувач камери

У програмі Hikvision iVMS-4200 створіть на реєстраторі окремого користувача
(наприклад `stream`) **лише з правом перегляду** камери 15. `admin`
використовувати не можна: цей логін ходитиме через інтернет.

Пароль беріть із літер і цифр — символи `@ : / #` ламають адресу потоку.

## Крок 2. Доступ до реєстратора ззовні

На роутері стадіону прокиньте на реєстратор **порт 554 (RTSP)**.

> **Важливо.** Реєстратор, відкритий усьому інтернету, рано чи пізно знайдуть
> боти: у Hikvision регулярно знаходять серйозні діри. Тому:
>
> - у налаштуваннях роутера дозвольте цей порт **лише з IP-адреси вашого
>   сервера** (у більшості роутерів це «Source IP» у правилі проброса);
> - оновіть прошивку реєстратора;
> - зовнішнім портом зробіть не 554, а щось випадкове, наприклад 55414
>   (тоді в `stream.env` пишіть саме його);
> - якщо роутер уміє VPN (WireGuard) — краще підніміть його й не відкривайте
>   порт зовсім.

Перевірте з дому у VLC: «Медіа → Відкрити URL» і
`rtsp://stream:ВАШПАРОЛЬ@АДРЕСА_СТАДІОНУ:554/Streaming/Channels/1501`
(замість АДРЕСА_СТАДІОНУ — зовнішня IP-адреса стадіону, `15` у номері каналу —
номер камери). Якщо відео пішло, сервер теж його візьме.

## Крок 3. YouTube

1. У YouTube Studio: **Створити → Почати трансляцію**.
2. Тип трансляції — **програмне забезпечення** (не вебкамера).
3. Доступ — **за посиланням** (unlisted), щоб трансляція не з'являлася
   в пошуку, але вставлялась на сайт.
4. Увімкніть **постійний ключ потоку**: тоді після перезапуску трансляція
   буде та сама, а не нова щоразу.
5. Скопіюйте **ключ потоку** — він піде в `stream.env`.

Хто має цей ключ, той може вести трансляцію від імені каналу. Тримайте його
як пароль.

## Крок 4. Сервер

Скопіюйте на сервер цю папку, далі:

```
cp stream.example.env stream.env
nano stream.env          # заповніть адресу, логін, пароль камери та ключ YouTube
sudo ./install.sh
```

`install.sh` поставить ffmpeg і створить службу, яка працює цілодобово
й сама перезапускається, якщо зв'язок обірвався.

Корисні команди:

```
systemctl status stadion-stream     # чи працює
journalctl -u stadion-stream -f     # що відбувається зараз
systemctl restart stadion-stream    # перезапустити після зміни stream.env
systemctl stop stadion-stream       # зупинити трансляцію
```

За хвилину-дві в YouTube Studio з'явиться картинка.

## Крок 5. Увімкнути на сайті

Зайдіть на сайт адмінакаунтом → меню акаунта → **Трансляція**. Вставте
посилання на канал YouTube, поставте «Показувати трансляцію на сайті»
і збережіть. Плеєр з'явиться на сторінці штучного поля.

Посилання на **канал** краще за посилання на конкретну трансляцію: сайт сам
показує те, що в етері зараз, і адресу не треба міняти після кожного
перезапуску.

## Якщо щось не так

- **«Камера не відповідає»** — порт не прокинутий, не та адреса чи номер
  камери, або пароль містить `@ : / #`.
- **У YouTube немає картинки** — перевірте ключ потоку й що в Studio
  трансляція не завершена вручну.
- **Сервер завантажений на 100%** — камера віддає H.265, і його доводиться
  перекодовувати. Або поставте в налаштуваннях камери H.264 (тоді сервер
  майже не працює), або візьміть VPS на 2 ядра.
- **Відео смикається** — зменште `VIDEO_BITRATE` у `stream.env`
  або знизьте роздільність камери в iVMS-4200.

## Скільки це коштує

| Що | Скільки |
|---|---|
| VPS | ≈ 4–6 € на місяць |
| YouTube | безкоштовно, глядачів скільки завгодно |
| Інтернет стадіону | один потік, ≈ 2–4 Мбіт/с вихідного каналу цілодобово |

## Лічильник людей

На цьому ж сервері може працювати програма з папки `camera-counter` — вона
рахує людей на полі. Її створювали для комп'ютера на стадіоні, але вона так
само працює й через інтернет: у `config.env` вкажіть ту саму зовнішню адресу
та порт, що й тут. Знімок вона бере по RTSP, якщо HTTP-порт реєстратора
назовні не прокинутий.
