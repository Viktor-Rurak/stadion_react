# Стадіон — React-версія сайту

Сайт спортивного комплексу «Дубівці», переписаний на React (збірник — Vite).

## Як запустити

Потрібен встановлений [Node.js](https://nodejs.org) (LTS-версія). Далі в цій папці:

```bash
npm install   # один раз: завантажити залежності
npm run dev   # запустити сайт для розробки (адресу покаже в терміналі)
```

Зібрати готову версію для публікації: `npm run build` (результат — у папці `dist`).

Сайт має кілька адрес (`/`, `/booking`). Під час розробки це працює само, а при
публікації хостинг треба налаштувати так, щоб будь-яка адреса віддавала
`index.html` (Netlify — файл `_redirects`, Vercel — `rewrites`). Інакше пряме
відкриття `/booking` покаже помилку 404.

## База даних (Supabase)

Сайт підключений до Supabase — проєкт `fudrgpsrbfeqwszsdaxf`
(https://fudrgpsrbfeqwszsdaxf.supabase.co). У базі три таблиці:

- **`profiles`** — дані реєстрації: логін, ім'я, прізвище, телефон, пошта.
  Email і пароль зберігає вбудований Supabase Auth (пароль захешований).
  Профіль створюється автоматично тригером при реєстрації.
  Увійти можна за **логіном або поштою** + пароль (функція `email_for_login`
  перетворює логін на пошту).

  Є також поле **`is_admin`** — адмінакаунт, за замовчуванням `false`.
  Поставити його можна лише в базі (SQL Editor у панелі Supabase):

  ```sql
  update public.profiles set is_admin = true where login = 'логін';
  ```

  Із сайту це поле змінити неможливо: користувачам дозволено оновлювати
  лише `login`, `first_name`, `last_name` і `phone`, тож призначити себе
  адміном не вийде навіть запитом в обхід інтерфейсу. У меню профілю
  адмін бачить позначку «Адмінакаунт».
- **`court_bookings`** — записи на корт. Правила гарантує сама база:
  максимум 2 години, час не перетинається з чужим записом, тільки в години
  роботи 06:00–24:00. Кожен запис має **вид спорту** (теніс / волейбол /
  баскетбол) і позначку **відкритий чи закритий**.
- **`booking_participants`** — хто грає в кожній грі. Організатор потрапляє
  сюди автоматично; інші — лише якщо гра відкрита й у ній є вільні місця.

### Відкриті та закриті бронювання

- **Закрите** (`isOpen: false`) — усе як було: корт зайнятий вашою компанією.
- **Відкрите** (`isOpen: true`) — гра з'являється в розкладі як така, до якої
  можна долучитися. Будь-хто натискає «Долучитися» і стає вашим суперником.

Кількість гравців (`max_players`) можна не вказувати — база сама поставить
звичайну для виду спорту: теніс 4, баскетбол 10, волейбол 12. Коли місця
скінчилися, база більше нікого не пускає.

**Правило «одна гра на день»** тепер рахує і власні записи, і долучення до
чужих: не можна і забронювати свій час, і піти грати до когось іншого того
самого дня. О 00:00 за київським часом настає нова дата — і все відкривається
знову, нічого чистити не треба.

Організатор не може «вийти» зі своєї гри — він може лише скасувати її
(тоді учасники автоматично звільняються).

Код для роботи з базою — у `src/lib/`:

| Файл                | Що вміє |
|---------------------|---------|
| `lib/supabase.js`   | підключення до бази (адреса + публічний ключ) |
| `lib/auth.js`       | `register(...)`, `login(логінАбоПошта, пароль)`, `logout()`, `getMyProfile()`, `isLoginAvailable(логін)` |
| `lib/bookings.js`   | `SPORTS`, `createBooking(...)`, `joinGame(id)`, `leaveGame(id)`, `cancelBooking(id)`, `getDaySchedule(дата)`, `getDaySlots(дата)`, `getGamePlayers(id)` |

Готовий список для випадаючого меню — константа `SPORTS`:

```jsx
import { SPORTS } from './lib/bookings.js';

<select value={sport} onChange={(e) => setSport(e.target.value)}>
  {SPORTS.map((s) => (
    <option key={s.value} value={s.value}>{s.label}</option>
  ))}
</select>
```

Два способи отримати розклад дня:

- `getDaySlots(дата)` — **для всіх**, зокрема незалогінених: лише час, вид
  спорту й кількість вільних місць. Для блоку «Вільні слоти» на головній.
- `getDaySchedule(дата)` — **лише для залогінених**: додатково ім'я
  організатора, скільки гравців уже є, і чи ви вже в цій грі
  (`is_mine`, `i_joined`). Телефони й пошта не видно нікому.

Усі функції у разі проблеми кидають помилку зі зрозумілим українським
текстом — її можна показувати користувачу як є.

### Приклад використання

```js
import { register, login } from './lib/auth.js';
import { createBooking, joinGame, getDaySchedule, kyivToday } from './lib/bookings.js';

// Реєстрація
await register({
  login: 'vitya',
  email: 'vitya@example.com',
  password: 'мій-пароль',
  firstName: 'Віктор',
  lastName: 'Прізвище',
  phone: '+380 50 111 22 33',
});

// Вхід — працює і за логіном, і за поштою
await login('vitya', 'мій-пароль');

// ЗАКРИТЕ бронювання: грає лише своя компанія
await createBooking({
  date: kyivToday(), startTime: '10:00', endTime: '12:00',
  sport: 'tennis', isOpen: false,
});

// ВІДКРИТЕ бронювання: шукаємо суперника
await createBooking({
  date: kyivToday(), startTime: '18:00', endTime: '20:00',
  sport: 'basketball', isOpen: true, note: 'Аматорський рівень',
});

// Подивитися розклад і долучитися до чужої відкритої гри
const games = await getDaySchedule(kyivToday());
const free = games.find((g) => g.is_open && g.free_slots > 0 && !g.is_mine);
if (free) await joinGame(free.id);
```

**Про листи підтвердження.** Зараз підтвердження пошти **вимкнене**, тож
реєстрація спрацьовує одразу й листи не надсилаються. Якщо увімкнути його
назад, кожна реєстрація надсилатиме лист. Вбудований поштовий сервіс Supabase дозволяє
лише **кілька листів на годину** на безкоштовному тарифі; коли ліміт вичерпано,
реєстрація падає з помилкою `over_email_send_rate_limit` (на сайті вона
показується українською).

Що з цим робити:

1. **Вимкнути підтвердження пошти** (зараз зроблено саме так) — Authentication → Sign In / Providers →
   Email, перемикач «Confirm email» (панель прокручується, перемикач може бути
   нижче видимої частини). Тоді листи не надсилаються взагалі, реєстрація
   спрацьовує миттєво й одразу входить у систему. Найзручніше для розробки.
2. **Зачекати близько години** — ліміт скидається сам.
3. **Підключити власний SMTP** (Project Settings → Authentication → SMTP
   Settings) — потрібно для реального запуску, бо вбудований мейлер Supabase
   не призначений для справжніх користувачів.

Supabase також відхиляє адреси на `example.com` і домени без поштових
записів — для тестів потрібна справжня адреса.

**Про вхід за логіном:** щоб він працював, функція `email_for_login` мусить
бути доступна ще не залогіненим користувачам. Це означає, що той, хто вгадає
чужий логін, побачить прив'язану до нього пошту. Для невеликого місцевого
проєкту це прийнятно; якщо захочете закрити й це — вхід треба переносити
в Supabase Edge Function, щоб пошта взагалі не поверталася на сайт.

## Запис на корт — окрема сторінка `/booking`

Запис живе на власній сторінці, яку React підвантажує лише тоді, коли людина
на неї переходить (`lazy` в `App.jsx`). Потрапити туди можна кнопкою
«Записатися» в шапці, кнопкою в картці корту або кліком по корту на плані.

Сторінка йде кроками в тому порядку, як думає людина:

1. **День** — сьогодні й 6 наступних днів.
2. **Час** — тривалість (1 / 1.5 / 2 години) і сітка з півгодинних клітинок:
   видно, що вільно, що зайнято, куди гра не вміститься і який час уже минув.
3. **Гра** — вид спорту (випадаючий список) і закрита чи відкрита гра;
   для відкритої — коментар для тих, хто долучиться.
4. **«Записатися»** — лише на цьому кроці гостя просять увійти або
   зареєструватися. Усе обране зберігається: після входу лишається
   натиснути кнопку ще раз.

Чужі відкриті ігри цього дня показані блоком «Шукають гравців» із кнопкою
«Долучитися». Якщо на обраний день у вас уже є гра, сторінка показує її
з кнопкою «Скасувати» (своя гра) або «Вийти» (чужа).

На комп'ютері підсумок і кнопка стоять праворуч, на телефоні — панеллю
внизу екрана.

## Новини та адмінпанель

- **`/news`** — сторінка новин, відкрита всім: фото, дата, заголовок, текст.
- **`/admin/news`** — адмінпанель: написати новину, змінити або видалити.
  Відкривається лише адмінам, решта бачить пояснення.

Адмін потрапляє в панель через меню профілю («Адмінпанель новин») або
кнопкою «Додати новину» на сторінці новин.

У формі три поля: заголовок, текст і фото (необов'язкове). Абзаци в тексті
зберігаються так, як їх набрали. Фото — jpg, png, webp або gif, до 5 МБ;
під формою одразу видно, що саме завантажиться.

**Де це лежить у базі:** таблиця `news` і сховище (кошик `news`) для фото.
Читати може будь-хто, а додавати, редагувати й видаляти — лише ті, у кого
в профілі стоїть `is_admin`. Це перевіряє сама база, тож звичайний
користувач нічого не змінить, навіть надіславши запит в обхід сайту.
Коли новину видаляють, її фото теж прибирається зі сховища.

## Вікно реєстрації та входу

Вікно відкривається кнопкою **«Увійти»** в шапці, а також на сторінці запису,
коли гість натискає «Записатися» чи «Долучитися». Закривається лише хрестиком.
Коли людина увійшла, у шапці замість «Увійти» з'являється її ім'я з меню
(пошта + «Вийти»).

Стан «хто увійшов» роздає `lib/AuthContext.jsx`. Будь-який компонент бере
його одним рядком:

```jsx
import { useAuth } from '../lib/AuthContext.jsx';

const { user, profile } = useAuth();
// user === null означає «гість»
```

Реєстрація перевіряє логін ще до відправки, пароль треба ввести двічі,
усі помилки показуються українською.

## Головна ідея структури

- **Дані** (тексти, слоти, описи об'єктів) лежать у `src/data/` — щоб змінити
  текст на сайті, не потрібно чіпати розмітку.
- **Розмітка** — в компонентах: кожна секція сторінки = один невеликий файл.
- **Вигляд** — повністю в `index.css`; компоненти лише вішають класи.

## Як працює інтерактивний план (PlanMap.jsx)

Для кожного майданчика збережений його силует у вигляді бітової маски
(209 × 118 точок). Коли миша рухається над планом, компонент обчислює, в яку
точку маски потрапляє курсор, і якщо там «одиниця» — запам'ятовує об'єкт у
стані `hoveredKey` і виставляє атрибут `data-hover` на контейнері. Усі
візуальні ефекти (затемнення плану, підйом об'єкта, поява підпису) описані в
`index.css` через цей атрибут. Клік по корту веде на сторінку запису, по інших об'єктах — до їхньої картки.
