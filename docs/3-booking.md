# 3. Запис на корт

Найскладніша частина сайту. Тут пояснено, як сторінка рахує час, звідки бере
розклад і чому правила неможливо обійти.

## Де що лежить

| Що | Де |
|---|---|
| сама сторінка, вся логіка вибору | `pages/BookingPage.jsx` |
| вибір дня | `components/booking/DayPicker.jsx` |
| сітка часу | `components/booking/TimeGrid.jsx` |
| вид спорту, закрита/відкрита гра | `components/booking/GameOptions.jsx` |
| картка гри з кнопкою | `components/booking/GameCard.jsx` |
| підсумок і кнопка «Записатися» | `components/booking/BookingSummary.jsx` |
| арифметика з часом і запити до бази | `lib/bookings.js` |

## Правила

| Правило | Хто стереже в базі |
|---|---|
| гра не довша за 2 години | перевірка `duration_max_2h` |
| лише з 06:00 до 24:00 | перевірка `within_open_hours` |
| час не перетинається з чужим записом | обмеження `no_time_overlap` |
| одна гра на день на людину (своя **або** чужа) | унікальність `one_game_per_day` |
| запис лише на найближчі 7 днів і не в минуле | політика доступу на `court_bookings` |
| долучитися можна лише до відкритої гри з вільними місцями | тригер `check_can_join` |
| організатор не може «вийти» — лише скасувати гру | тригер `protect_organizer` |
| записати можна тільки себе | політика доступу |

Сайт показує ці правила (сірі клітинки, підказки), але **не він їх стереже**.
Якщо хтось надішле запит в обхід сайту, база відмовить сама. Подробиці про
базу — у розділі 4.

«Оновлення о 00:00» нічим не запускається: правило звучить як «одна гра на
**дату**», тож коли настає нова дата за київським часом, людина просто може
записатися знову.

## Час — це хвилини від опівночі

Щоб не возитися з рядками на кшталт `'10:30'`, усередині сторінки час
зберігається числом хвилин від початку доби:

| Час | Число |
|---|---|
| 06:00 | 360 |
| 10:30 | 630 |
| 24:00 | 1440 |

Із числами легко рахувати: кінець гри — це `start + hours * 60`, наступна
клітинка — `+ 30`. Перекладають туди й назад дві функції з `lib/bookings.js`:

```js
timeToMinutes('10:30')   // 630
minutesToTime(630)       // '10:30'
```

Усі дати й години рахуються **за київським часом** (`kyivToday()`,
`kyivNowMinutes()`), щоб людина за кордоном бачила той самий розклад, що й
база.

## Що пам'ятає сторінка

`BookingPage` тримає вибір людини в кількох змінних стану:

| Змінна | Що це |
|---|---|
| `date` | обраний день, наприклад `'2026-10-14'` |
| `hours` | тривалість: 1, 1.5 або 2 |
| `start` | початок у хвилинах або `null`, якщо час ще не обрано |
| `sport` | `'tennis'`, `'volleyball'` чи `'basketball'` |
| `isOpen` | відкрита гра чи закрита |
| `note` | коментар для тих, хто долучиться |
| `games` | ігри цього дня, завантажені з бази |

Решта обчислюється з них на льоту: кінець гри, підпис дня, чи є в людини гра
на цей день.

## Звідки береться розклад

Щойно змінюється день або людина входить/виходить, сторінка питає базу:

```js
setGames(userId ? await getDaySchedule(date) : await getDaySlots(date));
```

- **Гість** отримує `getDaySlots` — лише час, вид спорту й кількість вільних
  місць. Жодних імен.
- **Залогінений** отримує `getDaySchedule` — ще й ім'я організатора та дві
  позначки: `is_mine` (це моя гра) і `i_joined` (я до неї долучився).

Обидві — функції в базі, які віддають рівно стільки, скільки можна показати.
Телефонів і пошт у розкладі немає ні для кого.

## Сітка часу

`TimeGrid` малює 36 клітинок — від 06:00 до 23:30 з кроком пів години. Для
кожної клітинки він визначає стан:

| Стан | Коли | Вигляд |
|---|---|---|
| `past` | сьогоднішній час, що вже минув | бліда, не натискається |
| `busy` | у цю пів години хтось грає | перекреслена, не натискається |
| `tight` | вільно, але гра обраної тривалості звідси не вміститься | інший колір, натискання показує пояснення |
| `free` | можна починати | звичайна |

Перевірку робить `canStartAt(start, hours, games, nowMinutes)`: проходить
кожні пів години від початку до кінця гри й дивиться, чи жодна не зайнята,
не в минулому й чи гра закінчується до 24:00.

Стан `tight` існує, щоб людина не гадала, чому клітинка «не працює».
Натискання викликає `whyCannotStart()`, і сторінка показує причину словами:
«З 22:30 гра на 2 год не вміститься: корт працює до 24:00».

Якщо обраний час раптом став недоступним (людина змінила тривалість або хтось
щойно записався), сторінка сама знімає вибір.

## Гість і кнопка «Записатися»

Гість може обрати все — день, час, вид гри — без акаунта. Увійти сайт просить
лише в момент натискання «Записатися»:

```js
if (!user) {
  setAskedToLogin(true);
  openAuth('register');
  return;
}
```

Обране при цьому нікуди не дівається, бо воно лежить у стані сторінки, а вікно
входу відкривається поверх неї. Після входу сайт підказує: «Ви увійшли.
Перевірте вибір і натисніть "Записатися"».

## Створення запису

```js
await createBooking({ date, startTime, endTime, sport, isOpen, note });
```

Це один рядок у таблицю `court_bookings`. Далі база робить решту сама:

1. перевіряє всі правила з таблиці вище;
2. якщо кількість гравців не вказана — ставить звичайну для виду спорту
   (теніс 4, баскетбол 10, волейбол 12);
3. записує організатора учасником гри (таблиця `booking_participants`).

Якщо база відмовила, `translateBookingError()` перекладає її відповідь на
людську мову: код `23P01` (перетин часу) стає «Цей час уже зайнятий», і так
далі.

## Закриті й відкриті ігри

- **Закрита** — корт зайнятий вашою компанією, у розкладі видно лише час.
- **Відкрита** — гра з'являється в блоці «Шукають гравців» із кнопкою
  «Долучитися». Так знаходять суперників.

Долучення — це рядок у `booking_participants`:

```js
await joinGame(game.id);
```

Тригер у базі перевіряє, що гра відкрита й у ній ще є місця. Правило «одна
гра на день» рахує і свої записи, і долучення до чужих разом.

## Коли в людини вже є гра на цей день

Сторінка шукає її серед завантажених:

```js
const myGame = games.find((g) => g.is_mine || g.i_joined);
```

Якщо знайшла — замість кроків 2 і 3 показує картку «Ваша гра цього дня»
з кнопкою «Скасувати» (якщо гра своя) або «Вийти» (якщо чужа).

Перед незворотною дією картка питає «Скасувати гру?» прямо в собі, двома
кнопками. Системне вікно браузера (`window.confirm`) тут не використовується
навмисно: у деяких браузерах воно заблоковане й мовчки відповідає «ні».

## Перевірка, що дія справді відбулася

Скасування й вихід із гри просять базу повернути видалені рядки:

```js
const { data } = await supabase.from('court_bookings').delete().eq('id', id).select('id');
if (data.length === 0) throw new Error('Не вдалося скасувати…');
```

Без цього була б пастка: якщо сесія вже закінчилась, база нічого не видалить,
але й помилки не дасть — і сайт радісно повідомив би «Скасовано».

## Як змінити правила

Міняти треба **в обох місцях** — на сайті й у базі, інакше сайт показуватиме
одне, а база дозволятиме інше.

| Що | На сайті (`lib/bookings.js`) | У базі |
|---|---|---|
| години запису | `OPEN_FROM`, `OPEN_TILL` | перевірка `within_open_hours` |
| максимальна тривалість | `DURATIONS` | перевірка `duration_max_2h` |
| скільки днів наперед | `nextDays(7)` у `BookingPage.jsx` | політика «Users can create own booking» |
| види спорту | `SPORTS` | тип `sport` і тригер `set_default_max_players` |

## Про старі записи

Записи за минулі дні з бази не видаляються — вони просто більше ніде не
показуються, бо сторінка питає розклад лише на найближчі 7 днів. Місця вони
займають мізерно. Якщо колись захочеться прибрати:

```sql
delete from public.court_bookings where booking_date < current_date - 30;
```
