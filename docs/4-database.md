# 4. База даних

База живе в Supabase — це хмарний сервіс, який дає базу даних PostgreSQL,
систему акаунтів, сховище файлів і відправку листів. Панель керування:
<https://supabase.com/dashboard>, проєкт `fudrgpsrbfeqwszsdaxf`.

## Головна ідея: правила стереже база

Код сайту працює в браузері відвідувача, а отже відвідувач може його змінити
або надіслати запит узагалі без сайту. Тому сайту **не можна довіряти**
жодну перевірку. Усе, що має бути неможливим, заборонено в самій базі
трьома способами:

| Спосіб | Що це | Приклад |
|---|---|---|
| **Перевірка** (CHECK) | умова на значення в рядку | гра не довша за 2 години |
| **Політика доступу** (RLS) | хто які рядки може читати й міняти | новини пише лише адмін |
| **Тригер** | код, який база виконує сама при зміні даних | не пускати в закриту гру |

## Таблиці

### `profiles` — користувачі

| Поле | Що це |
|---|---|
| `id` | той самий, що в акаунта в Authentication |
| `login` | унікальний, латиниця, 3–30 символів |
| `first_name`, `last_name` | до 60 символів |
| `phone` | до 20 символів |
| `email` | копія пошти з акаунта |
| `is_admin` | адмін чи ні |

Рядок створюється автоматично при реєстрації (тригер `handle_new_user`).
Кожен бачить **лише свій** профіль і може міняти лише ім'я, прізвище, логін
і телефон. Поле `is_admin` із сайту змінити неможливо.

### `court_bookings` — записи на корт

| Поле | Що це |
|---|---|
| `user_id` | хто організатор |
| `booking_date`, `start_time`, `end_time` | коли |
| `sport` | `tennis`, `volleyball` або `basketball` |
| `is_open` | чи можна долучитися іншим |
| `max_players` | скільки всього гравців |
| `note` | коментар, до 200 символів |

Запис можна створити й видалити, але **не можна змінити** — щоб перенести
гру, її скасовують і створюють заново.

### `booking_participants` — хто в якій грі

Один рядок = одна людина в одній грі. Організатор потрапляє сюди
автоматично. Саме тут живе правило «одна гра на день»: пара
«людина + дата» не може повторюватися.

### `news` — новини

`title`, `body`, `image_url` (посилання на фото), `author_id`, дати. Читають
усі, пишуть лише адміни. Самі фото лежать у сховищі Supabase, у кошику `news`.

### `field_occupancy` — скільки людей на полі

Один рядок на майданчик: `people_count` і `updated_at`. Читають усі. Записати
число напряму не може ніхто — лише функція `report_occupancy` із ключем
пристрою (розділ 6).

### `camera_devices` — пристрої-лічильники

Назва пристрою, до якого поля прив'язаний і відбиток його секретного ключа.
Ніхто з сайту цю таблицю не бачить узагалі.

### `live_streams` — налаштування трансляції

Один рядок на майданчик: канал чи ролик YouTube і вимикач `enabled`. Читають
усі, міняють лише адміни.

## Хто що може

| | Гість | Користувач | Адмін |
|---|---|---|---|
| читати новини, лічильник, трансляцію | ✓ | ✓ | ✓ |
| бачити розклад корту без імен | ✓ | ✓ | ✓ |
| бачити розклад з іменами організаторів | – | ✓ | ✓ |
| записатися, долучитися, скасувати **своє** | – | ✓ | ✓ |
| бачити й міняти **свій** профіль | – | ✓ | ✓ |
| бачити чужі профілі, телефони, пошти | – | – | – |
| писати, правити, видаляти новини | – | – | ✓ |
| налаштовувати трансляцію | – | – | ✓ |

Адмін — це не «суперкористувач»: чужих профілів і чужих записів він теж не
бачить і не може скасувати. Повний доступ має лише власник проєкту через
панель Supabase.

## Функції, які викликає сайт

Звичайні запити до таблиць обмежені політиками. Там, де треба віддати трохи
більше, ніж дозволяє політика, але не все, є функції:

| Функція | Хто викликає | Що віддає |
|---|---|---|
| `get_day_slots(дата)` | усі | розклад дня без імен |
| `get_day_schedule(дата)` | залогінені | розклад з іменем організатора й позначками «моя гра» |
| `login_available(логін)` | усі | вільний логін чи ні |
| `report_occupancy(ключ, число)` | програма-лічильник | нічого; оновлює число людей |
| `email_for_login(логін)` | лише серверна функція входу | пошту за логіном |
| `is_admin()` | політики доступу | чи адмін той, хто питає |

## Тригери — що база робить сама

| Коли | Що відбувається |
|---|---|
| створено акаунт | з'являється рядок у `profiles` |
| створено запис на корт | якщо гравців не вказано — ставиться звичайна кількість для виду спорту |
| створено запис на корт | організатор стає учасником гри |
| хтось долучається до гри | перевірка: гра відкрита й є місця |
| хтось виходить із гри | організатору вийти не дає |
| змінено новину | оновлюється дата редагування |

## Корисні запити

Виконуються в панелі Supabase → **SQL Editor**.

**Хто зареєстрований:**

```sql
select login, first_name, last_name, phone, email, is_admin, created_at
from public.profiles order by created_at desc;
```

**Записи на найближчі дні:**

```sql
select b.booking_date, b.start_time, b.end_time, b.sport, b.is_open,
       p.first_name, p.last_name, p.phone
from public.court_bookings b join public.profiles p on p.id = b.user_id
where b.booking_date >= current_date
order by b.booking_date, b.start_time;
```

**Хто долучився до ігор:**

```sql
select b.booking_date, b.start_time, p.login, bp.is_organizer
from public.booking_participants bp
join public.court_bookings b on b.id = bp.booking_id
join public.profiles p on p.id = bp.user_id
where b.booking_date >= current_date
order by b.booking_date, b.start_time, bp.is_organizer desc;
```

**Скасувати чужий запис** (наприклад, на прохання людини):

```sql
delete from public.court_bookings
where booking_date = '2026-10-14' and start_time = '18:00';
```

**Зробити адміном / забрати права:**

```sql
update public.profiles set is_admin = true  where login = 'логін';
update public.profiles set is_admin = false where login = 'логін';
```

**Видалити користувача** — не запитом, а через Authentication → Users →
Delete user (розділ 2).

## Чого не робити в панелі Supabase

- **Не видаляйте рядки в `profiles`** — акаунт лишиться «напіввидаленим».
- **Не вимикайте RLS** на таблицях («Disable RLS»): це зніме всі обмеження,
  і будь-хто зможе читати й міняти все.
- **Не публікуйте `service_role` ключ** (Project Settings → API). Він дає
  повний доступ в обхід усіх правил. На сайті використовується лише
  публічний ключ `sb_publishable_…`.

## Безкоштовний план засинає

Якщо до бази тиждень ніхто не звертався, Supabase її «присипляє». Сайт при
цьому відкривається, але новини порожні, а вхід не працює. Розбудити:
панель Supabase → проєкт → **Restore project**, за 2–3 хвилини все запрацює.

З живими відвідувачами цього не стається. Якщо сайт довго простоюватиме —
достатньо заходити на нього раз на кілька днів, або перейти на платний план.
