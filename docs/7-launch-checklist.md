# 7. Перед запуском

Що лишилось зробити, щоб показати сайт людям. Стан на 12 жовтня 2026.

## До публікації

- [ ] **Вирішити з лічильником людей.** Камера ще не підключена, а сайт уже
      обіцяє «камера рахує людей раз на хвилину». Або підключити, або
      тимчасово сховати: у `src/data/objects.js` прибрати `hasCounter` і
      `hasStream` у штучного поля та поправити `labelAction` і текст у
      `src/data/about.js`.
- [ ] **Пройти сайт очима відвідувача** — як гість, як гравець і як адмін,
      на комп'ютері й на телефоні. Суцільної перевірки ще не було.
- [ ] **Перевірити кнопку в листі.** У Supabase → Authentication → URL
      Configuration поле Site URL має починатися з `http://`. Потім
      зареєструвати тестовий акаунт і натиснути кнопку в листі.
- [ ] **Видалити тестові акаунти** `tester.dubivtsi` і `qwe`
      (Authentication → Users) і файл `test-account.local.md`.
- [ ] **Увімкнути в Supabase** (Authentication → Settings): «Leaked password
      protection» і мінімальну довжину пароля 8.
- [ ] **Прибрати `node_modules` із git.** Папку закомітили, коли ще не було
      `.gitignore`. Команда: `git rm -r --cached node_modules`, потім коміт.

## Публікація

- [ ] **Хостинг.** Сайт — це набір статичних файлів (`npm run build` → папка
      `dist`), тож підійде безкоштовний Netlify, Vercel або Cloudflare Pages.
- [ ] **Правило для адрес.** Хостинг має віддавати `index.html` на будь-яку
      адресу, інакше пряме відкриття `/booking` покаже помилку 404.
      На Netlify — файл `public/_redirects` із рядком `/* /index.html 200`.
- [ ] **Домен** і його підключення до хостингу.

## Одразу після публікації

- [ ] **Supabase → URL Configuration:** Site URL — справжня адреса сайту;
      у Redirect URLs додати `https://ваш-домен/**`. Без цього кнопки в
      листах вестимуть на `localhost`.
- [ ] **`index.html`:** у рядку `og:image` вписати повну адресу картинки
      (`https://ваш-домен/images/plan-base.png`) — інакше в месенджерах
      замість картинки буде порожньо.
- [ ] **Перевірити листи наживо:** реєстрація, підтвердження, «Забули пароль?».
- [ ] **Перший лист у «Спамі» позначити «Не спам»** — пошта стадіону нова,
      і Gmail вчиться на таких позначках.

## Камера (окремо, коли буде доступ)

- [ ] Дізнатися, хто має пароль від роутера стадіону й `admin` від реєстратора.
- [ ] Перевірити потік у VLC (адреса — у розділі 6).
- [ ] Сервер, порт 554 лише для його IP, користувач тільки для перегляду.
- [ ] Запустити `camera-stream` і `camera-counter`.
- [ ] Табличка про відеоспостереження біля поля й рядок про це на сайті —
      на полі бувають діти, і це вимога закону про персональні дані.

## Відомі обмеження

Не помилки, а свідомі спрощення. Варто знати про них заздалегідь.

| Що | Наслідок | Як виправити, якщо заважатиме |
|---|---|---|
| безкоштовний план Supabase засинає після тижня без відвідувачів | сайт відкривається, але без даних | Restore project у панелі або платний план |
| непідтверджений акаунт займає логін і пошту | якщо хтось зареєструвався на чужу адресу й закрив браузер, власник не зможе зареєструватися | додати автоприбирання непідтверджених за 24 години |
| немає кнопки «Видалити акаунт» | видаляти доводиться вручну на прохання | додати пункт у меню акаунта |
| запис можливий з 06:00 до 24:00, хоча стадіон відкритий цілодобово | вночі сайт каже «Корт працює з 06:00 до 24:00» | змінити години в `lib/bookings.js` і в базі (розділ 3) |
| рік «2026» у підвалі вписаний руками | у січні сам не зміниться | поправити `components/layout/Footer.jsx` |
| старі записи на корт не видаляються | нічого, вони просто лежать у базі | запит із розділу 3 |
| листи йдуть через Gmail | частина може потрапляти у «Спам» | свій домен і сервіс розсилок |
| пошта стадіону відкрито стоїть у підвалі | з часом прийде спам | форма зворотного зв'язку замість адреси |
