# 6. Камера: лічильник людей і трансляція

Обидві функції беруть картинку з однієї камери на штучному полі, але працюють
по-різному й незалежно одна від одної.

> **Стан на зараз:** код готовий і перевірений на тестових даних, але камера
> ще не підключена. Тому на сайті написано «Дані з камери зараз недоступні»
> і «Трансляція зараз не ведеться».

## Як улаштований відеонагляд на стадіоні

```
камери ──кабель──► відеореєстратор ──► роутер ──► інтернет
                   (пише на диск)
```

Камери самі нічого не зберігають — усе відео збирає **відеореєстратор**
(коробка з жорстким диском на стадіоні). Він уміє віддати відео тому, хто
попросить, за протоколом **RTSP**:

```
rtsp://логін:пароль@адреса:554/Streaming/Channels/1501
                                                  ││└─ 01 — основний потік
                                                  └┴── 15 — номер камери
```

На реєстратор не можна поставити свою програму, тому для лічильника й
трансляції потрібен ще один комп'ютер: або невеликий на стадіоні, або сервер
в інтернеті. Він підключається до реєстратора так само, як застосунок на
телефоні, тільки дивиться не людина, а програма.

## Лічильник людей

### Що робить

Раз на хвилину бере один кадр із камери, знаходить на ньому людей і надсилає
на сайт **лише число**. Самі кадри нікуди не передаються й не зберігаються.

```
реєстратор ──кадр──► counter.py ──число──► Supabase ──► сайт
                     (нейромережа)
```

### З чого складається

| Що | Де |
|---|---|
| програма | `camera-counter/counter.py` (Python) |
| налаштування | `camera-counter/config.env` — адреса камери, пароль, ключ |
| запуск одним кліком | `camera-counter/start.bat` |
| інструкція з установки | `camera-counter/README.md` |
| показ числа на сайті | `components/field/OccupancyInfo.jsx` |
| запит до бази раз на хвилину | `lib/occupancy.js` |

### Як програма рахує

1. `grab_snapshot()` просить у реєстратора знімок. Якщо не вийшло — бере один
   кадр із відеопотоку.
2. `find_people()` віддає кадр нейромережі YOLO, яка вміє знаходити людей на
   фото, і отримує рамку довкола кожної.
3. Якщо задано межі поля (`FIELD_ZONE`), рахуються лише ті, чиї ноги стоять
   усередині, — щоб не враховувати глядачів за сіткою.
4. `send_count()` надсилає число на сайт.

Якщо камера чи інтернет тимчасово зникли, програма не падає, а пробує знову
за хвилину.

### Як сайт дізнається, що число чесне

Записати число може лише той, хто знає **секретний ключ пристрою**. Він
лежить у `config.env` на комп'ютері з програмою. У базі зберігається не сам
ключ, а його відбиток — навіть якщо хтось побачить базу, ключа він не
відновить. Ключ дозволяє одне: оновити число для свого поля.

### Чому сайт іноді пише «Дані недоступні»

Сайт дивиться, **коли** число оновлювалось востаннє. Якщо минуло понад 10
хвилин — лічильник мовчить (вимкнули комп'ютер, зник інтернет), і старе число
показувати нечесно:

```js
const fresh = row?.people_count != null && minutesAgo < STALE_AFTER_MINUTES;
```

### Точність

Нейромережа помиляється: далеких, маленьких чи закритих іншими людей може
пропустити, вночі точність нижча. Тому на сайті написано «за даними камери».
Якщо рахує помітно менше, ніж є, — у `config.env` можна взяти точнішу модель
(`MODEL=yolo11s.pt`) або знизити поріг упевненості (`MIN_CONFIDENCE=0.25`).

### Замінити ключ пристрою

Якщо ключ загубився або потрапив не в ті руки — у панелі Supabase, SQL Editor:

```sql
select set_config('app.t', encode(extensions.gen_random_bytes(24), 'hex'), true);
update public.camera_devices
   set token_hash = encode(extensions.digest(current_setting('app.t'), 'sha256'), 'hex')
 where object_key = 'train';
select current_setting('app.t') as new_token;
```

Результат вставте в `config.env`, рядок `DEVICE_TOKEN=`.

## Трансляція

### Чому через YouTube

Браузер не вміє показувати потік із камери напряму. Потрібен посередник, і
найпростіший — YouTube:

```
реєстратор ◄──RTSP── сервер ──RTMP──► YouTube ──► плеєр на сайті
                    (ffmpeg)
```

Глядачі вантажать відео з YouTube, а не зі стадіону. Скільки б їх не було —
хоч сто на матчі — інтернет стадіону віддає рівно один потік, а сервер
лишається найдешевшим. Затримка 15–30 секунд.

### З чого складається

| Що | Де |
|---|---|
| програма для сервера | `camera-stream/restream.sh` |
| установка як служби | `camera-stream/install.sh` |
| налаштування | `camera-stream/stream.env` (створюється з `stream.example.env`) |
| покрокова інструкція | `camera-stream/README.md` |
| плеєр на сайті | `components/field/LivePlayer.jsx` |
| увімкнення на сайті | `pages/AdminLivePage.jsx` → адреса `/admin/live` |
| запити до бази | `lib/live.js` |

### Як працює серверна частина

`restream.sh` запускає програму `ffmpeg`, яка:

1. підключається до реєстратора й отримує відео;
2. перевіряє формат: якщо камера знімає в H.264 — передає як є (сервер майже
   не навантажений), якщо в H.265 — перекодовує, бо YouTube такого не приймає;
3. додає німу звукову доріжку — без звуку YouTube трансляцію не показує;
4. відправляє все в YouTube.

`install.sh` робить із цього службу: вона стартує разом із сервером і сама
перезапускається через 15 секунд, якщо зв'язок обірвався.

### Як працює сайтова частина

У таблиці `live_streams` лежить адреса каналу YouTube і вимикач. Адмін
заповнює їх на сторінці `/admin/live`. Плеєр будує адресу для вставки:

```js
// lib/live.js
`https://www.youtube.com/embed/live_stream?channel=${stream.youtube_channel_id}`
```

Адреса з **каналом**, а не з конкретною трансляцією, — навмисно: вона завжди
показує те, що в етері просто зараз, і її не треба міняти після кожного
перезапуску.

Паролів від камери ні в базі, ні на сайті немає — вони лише у `stream.env`
на сервері.

### Що потрібно, щоб увімкнути

1. Сервер (найдешевший VPS, Ubuntu).
2. На роутері стадіону — відкрити порт 554 **лише для IP-адреси сервера**.
3. На реєстраторі — окремий користувач тільки з правом перегляду.
4. Канал YouTube із дозволеними трансляціями.
5. На сервері — заповнити `stream.env` і запустити `install.sh`.
6. На сайті — `/admin/live`, вставити канал, увімкнути.

Подробиці кожного кроку — в `camera-stream/README.md`.
