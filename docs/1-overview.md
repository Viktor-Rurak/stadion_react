# 1. Як влаштований сайт

Цей розділ пояснює загальну механіку: що таке React-сайт, як він показує
сторінки, звідки знає, хто увійшов, і як улаштовані стилі. Після нього решта
розділів читається легко.

## Що відбувається, коли людина відкриває сайт

1. Браузер завантажує `index.html`. Там майже порожньо: є лише
   `<div id="root"></div>` і посилання на `src/main.jsx`.
2. `main.jsx` запускає React і каже йому: «намалюй компонент `App` усередині
   `#root`».
3. `App.jsx` дивиться на адресу в браузері й вирішує, яку сторінку показати.
4. Сторінка малює себе й, якщо треба, питає дані в бази (Supabase).

Сайт — це **одна сторінка, яка сама себе перемальовує**. Коли людина
переходить із головної на «Запис», браузер нічого не перезавантажує: React
просто прибирає один компонент і ставить інший. Тому переходи миттєві.

## React за п'ять хвилин

Увесь сайт складений із **компонентів**. Компонент — це функція, яка повертає
шматок сторінки. Ось найпростіший у проєкті, підвал
(`components/layout/Footer.jsx`):

```jsx
export default function Footer() {
  return (
    <footer id="contacts" className="footer">
      <span className="footer-brand">Стадіон</span>
      <span>Дубівці, Чернівецька область, 59334</span>
    </footer>
  );
}
```

Те, що схоже на HTML усередині JavaScript, називається **JSX**. Відмінності
від HTML мінімальні: `className` замість `class`, а у фігурних дужках `{ }`
можна писати JavaScript.

Чотири речі, які трапляються в кожному файлі:

**Props — те, що компоненту передали ззовні.** Як аргументи функції:

```jsx
<OccupancyInfo objectKey="train" compact />
//             ↑ кажемо, для якого поля    ↑ і що потрібен маленький варіант
```

**State — те, що компонент пам'ятає.** Коли стан змінюється, React
перемальовує компонент:

```jsx
const [menuOpen, setMenuOpen] = useState(false);
// menuOpen — поточне значення, setMenuOpen — як його змінити
<button onClick={() => setMenuOpen(true)}>Меню</button>
```

**Effect — «зроби це, коли щось сталося».** Найчастіше — завантажити дані:

```jsx
useEffect(() => {
  listNews().then(setItems);   // сходити в базу по новини
}, []);                        // [] означає «один раз, коли сторінка з'явилась»
```

**Умовний показ.** Показати щось лише за умови:

```jsx
{isAdmin && <Link to="/admin/news">Додати новину</Link>}
{loading ? <p>Завантажуємо…</p> : <NewsList />}
```

Цього досить, щоб читати будь-який файл проєкту.

## Сторінки та адреси (`App.jsx`)

`App.jsx` — це карта сайту. Кожен рядок означає «ця адреса → цей компонент»:

| Адреса | Файл у `pages/` | Що це |
|---|---|---|
| `/` | `HomePage.jsx` | головна: план, майданчики, «Як це працює» |
| `/booking` | `BookingPage.jsx` | запис на корт |
| `/news` | `NewsPage.jsx` | новини |
| `/fields/train` | `FieldPage.jsx` | сторінка майданчика |
| `/admin/news` | `AdminNewsPage.jsx` | адмінпанель новин |
| `/admin/live` | `AdminLivePage.jsx` | налаштування трансляції |
| `/auth/confirm` | `AuthConfirmPage.jsx` | сюди ведуть кнопки з листів |
| `/reset-password` | `ResetPasswordPage.jsx` | новий пароль |
| будь-що інше | `NotFound` (в `App.jsx`) | «Такої сторінки немає» |

Усі сторінки, крім головної, підключені через `lazy(...)`. Це означає, що
браузер завантажує код сторінки лише тоді, коли людина на неї переходить, —
головна від цього відкривається швидше.

Щоб **додати сторінку**: створіть файл у `pages/` й додайте в `App.jsx` два
рядки за зразком сусідніх.

## Каркас (`components/layout/Layout.jsx`)

Шапка, підвал і вікно входу однакові на всіх сторінках, тому вони описані
один раз у `Layout`. Сторінка вставляється посередині, на місці `<Outlet />`:

```
┌────────────── Header ──────────────┐
│                                    │
│   <Outlet />  ← тут сторінка       │
│                                    │
├────────────── Footer ──────────────┤
└─ AuthModal (вікно входу, зазвичай сховане) ─┘
```

Вікно входу живе в `Layout`, а відкривати його треба і з шапки, і зі сторінки
запису. Тому `Layout` роздає сторінкам функцію `openAuth`:

```jsx
// у будь-якій сторінці
const { openAuth } = useOutletContext();
openAuth('login');     // відкрити на вкладці «Вхід»
openAuth('register');  // «Реєстрація»
openAuth('forgot');    // «Забули пароль?»
```

## Хто увійшов (`lib/AuthContext.jsx`)

Знати, хто зараз увійшов, треба багатьом компонентам: шапці — щоб показати
ім'я, сторінці запису — щоб дозволити запис, адмінпанелі — щоб пустити чи ні.
Щоб не передавати це через десять компонентів, є спільне «сховище» —
`AuthContext`. Будь-який компонент бере з нього дані одним рядком:

```jsx
const { user, profile, isAdmin, loading } = useAuth();
```

| Що | Значення |
|---|---|
| `user` | акаунт (пошта, id) або `null`, якщо це гість |
| `profile` | логін, ім'я, прізвище, телефон із таблиці `profiles` |
| `isAdmin` | `true`, якщо в профілі стоїть позначка адміна |
| `loading` | `true`, поки сайт ще перевіряє, чи людина входила раніше |

Як це працює всередині: при старті `AuthContext` питає Supabase «чи є
збережена сесія?» і підписується на зміни. Щойно людина увійшла чи вийшла —
навіть в іншій вкладці — усі компоненти, які викликали `useAuth()`,
перемальовуються самі.

## Спілкування з базою (`lib/`)

Жоден компонент не звертається до бази напряму. Усе йде через файли в `lib/`:

| Файл | За що відповідає |
|---|---|
| `supabase.js` | підключення: адреса бази й публічний ключ |
| `auth.js` | реєстрація, вхід, вихід, відновлення пароля |
| `bookings.js` | записи на корт і вся арифметика з часом |
| `news.js` | новини та фото до них |
| `occupancy.js` | скільки людей на полі |
| `live.js` | налаштування трансляції |
| `AuthContext.jsx` | хто зараз увійшов |

Кожна функція тут робить одну річ і в разі проблеми кидає помилку з готовим
українським текстом. Тому компоненти виглядають однаково:

```jsx
try {
  await createBooking({ ... });
  setMessage({ type: 'success', text: 'Ви записані' });
} catch (e) {
  setMessage({ type: 'error', text: e.message });  // текст уже зрозумілий людині
}
```

Публічний ключ у `supabase.js` тримати в коді безпечно: він дозволяє лише те,
що дозволяють правила в самій базі (див. розділ 4).

## Стилі (`styles/`)

Компоненти лише називають класи, а вигляд описаний окремо:

| Файл | Що в ньому |
|---|---|
| `index.css` | нічого свого — лише підключає решту в правильному порядку |
| `tokens.css` | змінні: кольори, шрифти, відступи |
| `base.css` | фон, шрифт, посилання |
| `ui.css` | спільні «цеглинки»: кнопки, поля, сповіщення, каркас сторінки |
| `header.css`, `footer.css` | шапка з меню й бургером, підвал |
| `home.css` | головна: план, картки, «Як це працює» |
| `auth.css` | вікно реєстрації та входу |
| `booking.css` | запис на корт |
| `news.css` | новини й адмінпанель |
| `field.css` | лічильник людей і плеєр |

**Як знайти стиль елемента.** Подивіться його `className` у компоненті,
наприклад `btn-primary`. Початок назви підказує файл: `btn-` → `ui.css`,
`auth-` → `auth.css`, `news-` → `news.css`. Або просто пошук по папці `styles/`.

**Змінні.** Кольори не вписані в кожне правило, а названі в `tokens.css`:

```css
:root {
  --accent: oklch(0.72 0.13 148);   /* фірмовий зелений */
  --bg: #0f1214;                    /* фон сторінки */
}
```

Змінити зелений на інший колір по всьому сайту — це поправити один рядок.

**Телефон і комп'ютер.** Правила для вузьких екранів загорнуті в `@media`:

```css
@media (max-width: 900px) {
  .burger { display: flex; }   /* на екранах до 900px показати «бургер» */
}
```

**Стани.** Класи, що починаються з `is-`, означають стан: `is-active`
(вибрана вкладка), `is-busy` (зайнятий час), `is-error` (сповіщення про
помилку). Компонент додає їх за умовою:

```jsx
className={tab === 'login' ? 'auth-tab is-active' : 'auth-tab'}
```

## Дані окремо (`data/`)

Тексти, які може захотіти поправити людина без досвіду програмування,
лежать окремо від розмітки:

- `objects.js` — три майданчики: назва, опис, підпис на плані, куди веде клік;
- `about.js` — кроки інструкції «Як це працює»;
- `planMasks.js` — силуети майданчиків для плану (згенерований файл, руками
  його не правлять — див. розділ 5).

Компонент просто проходить по списку й малює картку на кожен запис:

```jsx
{OBJECTS.map((object) => <ObjectCard key={object.key} object={object} />)}
```

Тому додати четвертий майданчик — це дописати запис у `objects.js`,
а не копіювати розмітку.
